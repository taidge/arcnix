# 服务器管理工作台

Arcnix 的定位是通过 SSH 驱动常见服务器管理操作的桌面应用。文件传输属于其中一个模块，软件管理、资源监控、服务和日志应有各自清晰的工作区，不把所有功能挤到文件工具栏中。

## 已实现：系统软件

- 自动识别 Linux 发行版、APT / DNF / YUM / APK / Pacman、root 与 sudo 可用性。
- 当前完整实现 Debian / Ubuntu APT：搜索、查看已安装包及版本、安装模拟预览、确认安装、更新软件源索引。
- 软件管理只需要 SSH；SFTP 子系统可缺省，不影响命令执行和软件管理。
- UI 不发送任意命令：后端生成类型化计划并绑定会话和预览请求标识，确认只能消费同一会话中的计划一次，切换服务器后计划失效。
- 输入严格校验并引用；通过 apt-cache 元数据验证精确包名，避免 apt 的旧式正则回退。安装模拟拒绝 Remv，执行继续使用 --no-remove。
- sudo 密码仅传入 stdin，显示命令和计划不含秘密。输出按字节流过滤原样凭据，覆盖跨分块和 UTF-8 边界。客户端不会持久化该密码。
- 长任务实时排空 stdout / stderr，每路仅保留有限尾部；页面保留有界日志，显示真实退出码。完成后重新查询软件状态。
- 执行期间固定当前会话，不能手动切换服务器或断开；不提供会误导为可安全回滚的“取消安装”。关闭应用、超时或断线后结果可能未确认，重连后应查询实际状态。

更新软件源索引和升级已安装包是两个不同操作。目前仅提供前者；尚未实现批量升级、卸载、任务断线托管或完整系统回滚。

## 已实现：资源概览与系统日志

资源模块读取 Linux 的 `/proc/stat`、`meminfo`、`loadavg`、`uptime`、`net/dev` 和 `df -Pk`，采用类型化快照，并为缺失指标保留不可用状态。CPU 使用率和网络速率由同一连接的连续快照计算；首个快照等待下一次采样，不填充模拟值。界面只显示数值与表格，暂不绘制图表。

日志模块读取 journalctl 的 JSON 快照，支持时间范围、服务单元和级别查询；也可查看固定白名单内当前账户可读的传统日志文件。查询参数校验后生成只读命令，无任意路径或 shell 输入，不自动 sudo。日志数量和响应大小受限，多行消息作为文本显示，错误和权限提示保留。

两个模块只在当前页面自动刷新，单个模块最多一个待处理请求。SSH 仍为串行工作通道；文件传输或系统任务占用连接时，采样可能延后，不积累定时请求。切换连接清空旧数据，过期响应按连接代数和请求标识拒绝。

依据：[Linux proc](https://www.kernel.org/doc/html/latest/filesystems/proc.html)、[journalctl](https://www.freedesktop.org/software/systemd/man/latest/journalctl.html)。

## 后续模块

1. 资源监控图表：基于当前数值采样框架增加历史缓冲、曲线与时间范围；支持其他远程系统。
2. 其他包管理器适配：DNF / YUM、APK、Pacman，在各自真实环境验证查询、预览和权限模型后开放执行。
3. 系统服务：服务列表、状态、启动/停止/重启及对应日志。
4. 常见维护任务：通过独立操作适配器提供预览、权限、任务日志和结果，不建设无限制命令按钮集合。

这些后续能力没有以模拟图表或不可用按钮展示在当前产品中。

## 命令依据

当前 APT 操作依据官方手册：

- [Debian apt-get](https://manpages.debian.org/testing/apt/apt-get.8.en.html)：模拟运行、安装、更新索引和 --no-remove。
- [Debian apt-cache](https://manpages.debian.org/testing/apt/apt-cache.8.en.html)：软件包搜索和元数据查询。
- [Debian dpkg-query](https://manpages.debian.org/testing/dpkg/dpkg-query.1.en.html)：已安装包状态、版本和结构化字段。
- [Sudo 手册](https://www.sudo.ws/docs/man/sudo.man/)：非交互与 stdin 密码参数。

## 验证边界

83 项 Rust 测试（包含真实回环 SSH/SFTP、资源数值、日志、流式命令及包管理固定响应测试）通过；19 组实际 WebView 界面检查通过。包括没有 SFTP 的 SSH 连接也能执行软件查询、计划不能重放、长输出排空、stdin 私密输入、超时后会话复用、安装后状态刷新、执行期间服务器锁定，以及命令注入与凭据分块过滤。

软件管理集成使用固定的包管理响应，未实际运行 Linux apt 或安装软件。具体发行版的软件源、sudo 策略、安装脚本和服务行为仍需要真实服务器环境验收。
