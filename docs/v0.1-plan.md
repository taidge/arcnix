# Arcnix 0.1 — 桌面 SSH / SFTP 工作台

## 定位

仅提供桌面应用，采用 Rust + Glory + Sapid。以 FileZilla 的高密度双栏文件工作流为基础，将服务器组织、连接、文件传输和服务器信息放在同一窗口。首个运行验证平台为 Windows，远程信息采集面向 Linux，SFTP 文件功能不依赖 Linux shell。

## 第一版范围

| 模块 | 第一版交付 |
| --- | --- |
| 站点管理 | 多服务器增删改、名称/地址搜索、分组组织；配置保存至用户应用数据目录 |
| 连接 | SSH 密码、私钥和私钥口令；首连显示指纹并显式信任，已知主机指纹不符时拒绝连接 |
| 文件工作台 | 左侧本地、右侧远程；路径输入、上级目录、刷新、文件选择、大小与修改时间 |
| SFTP | 单文件上传/下载，可连续加入队列；进度、取消、失败重试；默认拒绝覆盖 |
| 目录操作 | 新建目录、重命名；不提供递归删除 |
| 服务器信息 | 主机、系统、运行时间、内存、磁盘；只读命令预设与结果 |
| 反馈 | 连接状态、操作日志、传输成功/失败/取消状态；后台 I/O 避免阻塞界面 |

一个窗口维护一个活动 SSH 会话，可以保存并切换多台服务器。分组为单层，删除分组将其中服务器移入“未分组”。不把密码或私钥口令写入配置。私钥只保存路径。

## 布局

顶部：产品名称、当前连接、连接/断开与服务器管理入口。

左侧：服务器搜索、分组与站点列表。

主区：本地/远程路径栏、工具栏和文件列表并排；未连接远程区提供明确空状态。

底部：传输队列与操作日志；服务器信息通过独立面板展示。

## 架构与并行分工

- `arcnix-core/model`：共享配置、文件和传输类型。
- `arcnix-core/store`：配置存储、验证、分组与主机信任记录。
- `arcnix-core/local`、`remote`：本地文件和 SSH/SFTP 操作，独立于 UI。
- `arcnix-desktop`：Glory 原生 Rust 状态与界面构建、Sapid 组件、Wry 桌面宿主；后台工作线程执行阻塞 I/O。

三个 agent 分别负责 SSH/SFTP、配置存储、桌面 UI；主 agent 负责共享接口、集成、验证和文档。

## 验收重点

1. 新建分组与服务器，重启后配置可恢复；错误配置不会静默丢失。
2. 首次连接必须确认指纹；指纹变化不能发送认证秘密。
3. 浏览真实本地目录与真实 SFTP 目录，中文和含空格文件名正常。
4. 上传后下载，文件字节一致；已有目标不会被意外覆盖。
5. 取消传输有明确状态，传输的临时文件清理，失败支持重试。
6. 网络错误有可理解反馈，UI 保持响应。
7. 工作区 `cargo test`、格式和 Clippy 检查，实际桌面窗口启动验证。

## 后续版本

交互式终端、递归目录传输、拖放、断点续传、目录同步、远程文件编辑、代理/跳板机、SSH Agent、凭据库、多个同时活动会话、历史指标图表与服务/容器管理。

## 构建约定

遵循调用者环境与 Cargo 配置，不重定向 Cargo home、target、TEMP/TMP。产物目录通过本工作区 `cargo metadata --no-deps --format-version 1` 确定。不使用 Docker 构建。
